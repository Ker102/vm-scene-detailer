VM_SceneDetailer v2 - USAGE (Blender 5.2)
=========================================

WHAT THIS IS
------------
A Geometry Nodes "semantic architectural application" engine:
  * VM_SceneDetailer - scatters props, FITS architectural parts onto walls,
    and applies CLADDING row courses (shingles/planks), with per-zone surface
    materials on the base mesh.
  * VM_RoofCap - generates a pitched gable/hip roof over any mesh with a flat top.

Files in this folder:
  VM_SceneDetailer.blend / VM_Starter.blend - engine + demo scenes
  VM_RoofCap.blend - same engine, kept as a dedicated roof-generator file
  build_engine.py - deterministic generator (rebuilds everything from scratch)
  pack_ingest.py - GENERIC ZERO-CONFIG asset-pack adapter (see PACK ADAPTER
    below); ingests any glTF/OBJ pack into classified variant collections
  <Pack>_ingest.json - per-pack ingest reports (decisions, scale factors,
    quarantine reasons) for WornWoodenDoorsPack + the 4 window packs
  preview_*.png - rendered proofs for each stage (incl. preview_door_closeup.png,
    preview_window_closeup.png and preview_starter_house.png: doors/windows
    mounted against the wall planks)
  verification_v2.json - numeric proof log
  VM_SceneDetailer.blend1 - Blender's automatic backup of the previous save
  (the r*.png / starter_preview.png files are leftovers from the v1 build)

------------------------------------------------
* LOOK AT: "StarterCube" + "StarterGround" (near x=0, y=-40) - the v2
  worked example described below. The preview_starter_house.png render is
  exactly this.
* IGNORE/DELETE FREELY: "HouseA" and "HouseB" (near the origin) and their
  floating platform + furniture - these are the OLD v1 demo scenes kept for

QUICK START: MAKE A LITTLE HOUSE FROM A CUBE
--------------------------------------------
1. Open VM_Starter.blend. Look at the object "StarterCube" (at x=0, y=-40).
   It is a plain 2m cube with five modifiers - that is the whole recipe
   (order matters, top to bottom in the modifier stack):
     a. VM_SceneDetailer      -> wall plank cladding (run BEFORE the roof so
                                 gable ends are not over-clad)
     b. VM_RoofCap            -> adds the pitched roof
     c. VM_SceneDetailer      -> roof shingle courses
     d. VM_SceneDetailer      -> fitted doors (VM_Doors collection)
     e. VM_SceneDetailer      -> fitted windows (VM_Windows collection, v2.2)
   "StarterGround" has a sixth VM_SceneDetailer in Scatter mode for debris.
2. To build it yourself on any cube:
   - Add > Mesh > Cube (2m). Optionally set its origin so the base sits at z=0.
   - Modifier Properties > Add Modifier > Geometry Nodes, pick "VM_SceneDetailer".
     Set Placement Mode = Cladding for the walls (see panels below).
   - Add another Geometry Nodes modifier, pick "VM_RoofCap".
     Pitch 35 deg, Overhang 0.25 m, Style Gable, Roof Material = your material.
   - Stack as many VM_SceneDetailer modifiers as you want (one per job:
     wall cladding, roof cladding, doors, debris...). Later modifiers see the
     geometry produced by earlier ones, so roof cladding automatically lands on
     the VM_RoofCap roof. Sampling always ignores earlier INSTANCES, so tiles
     never get clad with more tiles.
3. Press F12. Done.

WORLD-SPACE SIZING (v2.4.1) - 'make the house bigger' works
-----------------------------------------------------------
Every DISTANCE value in the panels below is WORLD METERS and does NOT stretch
when you scale the dressed object in OBJECT MODE with the transform left
unapplied (the normal 'select the house, press S, drag' workflow):
  * cladding tiles keep their tile size - a scaled (x1.6) building simply gets
    MORE courses/slots (counts follow the same course formula in world space),
    tiles never turn into 1.6x 'blocks';
  * doors/windows/debris keep their real size too (their dimensions come from
    the variant models); only their FIT placement offsets follow the meters;
  * Sill Height 0.9 = 0.9 WORLD meters above the face base whatever the object
    scale (it used to read 0.9 x z-scale, so windows sat visually high on
    scaled buildings).
Mechanics: the node groups read the host's own transform (Blender 5.2
Self Object -> Object Info) and divide each local quantity by the
world-meters-per-meter factor of its direction. At object scale (1,1,1) all
factors are exactly 1, so un-scaled scenes are bit-identical to v2.4.
Sockets covered: Slot Width, Row Height, Jitter, Embed, Backing Offset,
Sill Height, Min Face Width/Height, Ground Tolerance, Surface Offset,
Vertical Range Min/Max, Proximity Radius, and for VM_RoofCap: Overhang,
Min Roof Face Size and Pitch (a WORLD angle - the roof keeps its pitch on
scaled buildings). Density is a COUNT knob (instances per m^2 of the mesh
as modeled) and deliberately keeps its v2.4 semantics - it is NOT a
world-meter socket. (Rescaling it with the object transform was built and
tested: the Max Instances cap keeps the FIRST N candidates in face order,
so world-m^2 density floods the early faces of a scaled building and starves
later ones until capped door/window layers cannot find any clean layout.)
Edit-mode scaling
(moving vertices) keeps its v2.4 behavior exactly. Verification: the
"CompoundWorldRef" rig (same compound scaled in edit mode) dresses identically
to the object-scaled "CompoundScaled" - see results.world_space in
verification_v2.json.
Honest limits: on faces that are NOT axis-aligned to the object (e.g. roof
slopes under a NON-UNIFORM scale) tile size is compensated per axis but a
small residual shear can remain; Proximity Radius uses the volume-mean scale
factor (exact for uniform scale only); rotated unapplied transforms are
absorbed into the per-direction factors but the Vertical Range mask follows
the object's local z.

THE VM_SceneDetailer PANELS
---------------------------
Assets
  Primary Props      collection of variants to instance (one object per variant)
  Debris/Trash Props collection of debris variants
  Debris Ratio       0..1 fraction of slots that get debris instead of primary

Placement
  Placement Mode     Scatter = v1 random scatter over ALL faces (old default)
                     Fit     = architectural placement on zone faces
                     Cladding= regular row/slot courses on zone faces
  Embed              Fit: sinks the instance's BACK face (the wall-contact face,
                     see ASSET PREP RULES) into the placement plane by this
                     depth. Final offset along the face normal = Backing Offset
                     - Embed. (0.02 default = tiny sink.)
  Backing Offset     Fit (new in v2.1): distance from the sampled face along the
                     OUTWARD normal to the placement plane the variant's back
                     face lands on. Set it to the surface buildup in front of
                     the base wall (e.g. the cladding layer thickness) and the
                     fitted part sits ON the cladding instead of behind it.
                     Default 0.0 = old behavior (placement plane = base wall).
  Fit Jitter         Fit: tiny random rotation in radians (0 = perfectly flush)
  Stand On Face Base Fit (v2.4, renamed from 'Drop To Ground'): per-face
                     anchoring - the instance base sits on ITS OWN placement
                     face's lowest edge + Sill Height, never the host bounding
                     box. On a stepped compound, a door on a face whose bottom
                     is at z=1.2 stands at z=1.2 (and a door on a ground wall
                     stands at z=0 - nothing is dragged underground).
  Sill Height        Fit (v2.4): instance base = face base + Sill Height.
                     Doors use 0.0, windows ~0.9. With Stand On Face Base off
                     it is simply added to the sampled point height.
  Min Face Width     Fit (v2.4): skip placement faces narrower than this
                     (default 0.6 m). Step-wall fragments never get parts.
  Min Face Height    Fit (v2.4): skip placement faces shorter than this
                     (default 1.2 m).
  Ground Floor Only  Fit (v2.4): only faces whose base sits within Ground
                     Tolerance of the host's lowest point get parts - use it
                     for doors that must never climb steps.
  Ground Tolerance   Fit (v2.4): acceptance band for Ground Floor Only (0.1 m)
  Row Height         Cladding: course pitch along the stack direction (0.22 m)
  Row Overlap        Cladding: courses are drawn 1/(1-Overlap) taller so they
                     overlap like shingles (0.35 = 35% covered)
  Stagger            Cladding: row phase shift in fraction of slot width
                     (0.5 = classic half-offset shingle bond)
  Jitter             Cladding: per-slot position noise (0.01 m)
  Slot Width         Cladding: tile width in meters. Slot pitch =
                     Slot Width * (1 - Row Overlap). Set it to your variants'
                     average width (0.25 for the generated shingles, 2.0 for
                     the generated planks). GN cannot measure variants, so this
                     is explicit rather than automatic. Tiles are scaled to fit
                     their slot width, and slots/rows are spread to exactly
                     cover the face, so nothing juts past the face edges on
                     quad faces. On triangles (gable ends) courses are laid out
                     on the face bounding box - prefer small tiles there, or
                     clad the walls before adding VM_RoofCap.

Distribution
  Density            instances per square meter (Scatter and Fit modes)
  Seed               deterministic random seed
  Surface Offset     Scatter: offset along the face normal (v1 behavior)
  Align To Normal    Scatter: Z-align instances to the face normal (v1 behavior)

Variation
  Random Rot X/Y/Z   Scatter random rotation amounts (v1)
  Scale Min/Max      random uniform scale; Cladding additionally stretches the
                     tile height by 1/(1-Row Overlap)
  Tint Amount        per-instance tint stored in the instance color attribute

Zones
  Face Zone          All / Walls / Roof / Floor - which faces Fit and Cladding
                     sample. Scatter ignores this (v1 = all faces).
  Wall Slope         faces with |N.z| <= this are Walls (default 0.35)
  Roof Slope Min     v2.4: Roof is a SLOPE BAND, not a half-space. Roof =
  Roof Slope Max     Roof Slope Min <= N.z < Roof Slope Max (defaults
                     0.55 / 0.92). A 35 deg pitched roof has N.z ~ 0.82 =
                     Roof; FLAT tops (N.z ~ 1.0) are NOT roof, so flat step
                     decks are never shingled. Floor = N.z <= -Roof Slope Min
                     OR N.z >= Roof Slope Max (flat bottoms AND flat decks -
                     clad a deck with Face Zone = Floor or leave it bare).

Materials
  Wall/Roof/Floor Material
                     applied to the BASE MESH (the host itself) by zone via
                     Set Material. Leave a socket EMPTY to leave that zone's
                     existing material alone (safe for old scenes). Instanced
                     props always keep their own materials.

Masks / Cleanup
  (unchanged from v1) random mask, vertical gradient mask, proximity mask,
  Max Instances hard cap (exact).

PLACEMENT MATH (v2.5 - the 'Slots' panel)
-----------------------------------------
HouseCraft-style opening placement for Fit mode: doors/windows are not random
points, they are per-face COLUMN SLOTS with enforced spacing - the same math
the reference houses use (no duplicate doors next to each other, no windows on
top of each other, aligned sill rows, wall-length-derived counts).

THE RULES (all distances are WORLD meters):
1. WALLS ONLY, NEVER ROOF-ADJACENT. Openings land on wall-zone faces that are
   not RoofCap-generated (vm_roofgen), whose BASE EDGE is at most 'Max Base
   Height' above the host's lowest point, and - with 'Ground Floor Only' ON
   (the v2.5 default for doors) - whose base is within 'Ground Tolerance' of
   the host z-min. A wall segment whose base sits ON a roof surface (the tower
   strip above a wing roof) can therefore NEVER receive an opening: the
   reported "door standing on the wing roof" case is impossible by default.
   Explicit upper doors: set Ground Floor Only OFF and raise Max Base Height.
2. COLUMN SLOTS FROM THE WALL WIDTH. Count Mode 'Per Width' = one opening per
   'Openings Per Width' meters of wall: columns = floor(face width / N), min 1
   (doubling the wall width doubles the count). 'Explicit' = fixed
   'Slot Count' columns. Columns evenly fill the face width; a face too narrow
   for two columns gets a single centered opening (a lone opening has no
   neighbour, so the gap law never starves narrow walls).
3. GAP LAW (no touching, no overlapping columns). The column pitch is clamped
   to Opening Width + Min Gap X + 2*Slot Jitter: as long as your variants are
   no wider than 'Opening Width', horizontal neighbours can never touch or
   overlap and their bbox gap is always >= Min Gap X.
4. ONE ROW BY DEFAULT (no stacking). 'Slot Rows' x 'Row Spacing'; the row pitch
   is clamped to at least Opening Height + Min Gap Z so nothing stacks on top
   of anything, and a row is dropped entirely if the opening would not FIT on
   its wall (row base + Opening Height <= face top) - no floating rows.
5. COMMON SILL LINE ('Sill Line' = 'Common Z', the default): every opening's
   base row sits on ONE shared world-z line = host zmin + Sill Height, across
   ALL walls of the object - window rows align exactly like the reference
   houses (measured: spread <= 0.01 m). Faces whose base edge is above the
   sill line get no slots (openings never stand on roofs). 'Face Base' keeps
   the v2.4 per-face sill (face base + Sill Height) for upper-floor work.
6. NO DUPLICATE NEIGHBOURS ('No-Repeat' ON by default): the variant of a slot
   is a deterministic cycle (col + 17*row + 7*face + Seed) - two adjacent
   slots can NEVER pick the same variant for any collection of 2+ variants
   (only a collection of exactly 17 variants could alias vertically).
7. SLOT JITTER is small random noise ALONG THE WALL ONLY (horizontal) so the
   shared sill line stays exactly aligned while the columns read organically.

CROSS-LAYER DOOR/WINDOW SPLIT (the socket semantics of the demo stacks):
a door layer takes 'Column Select' = 'First Only' (the first column of every
face's grid) and a window layer takes 'Skip First' (the columns beside it).
Keep 'Count Mode' + 'Openings Per Width' + 'Min Gap X' identical on layers
that share walls so both compute the SAME column grid - then door and window
layers can never collide by construction (verified: zero pairwise bbox
intersections on TowerWing, CompoundTest and a 12 m wall).
WATCH OUT (v2.6, the UserShape2 lesson): 'Skip First' empties the whole
window layer when the gap law clamps every face to ONE column (walls narrower
than 2*Opening Width + Min Gap X). On small/cottage-scale massing use
'Column Select' = 'All' or the Exact N count mode below instead of the split.

OPENING FIT (v2.6) - openings that do not fit their wall
--------------------------------------------------------
Opening Fit   'Scale To Face' (default) = an opening taller/wider than its
              face is SHRUNK to the available space (the instance is scaled
              by the fit factor; the gap law still holds and the base stays
              exactly on the sill line). 'Drop' (v2.5 behavior) = the row is
              rejected outright and NOTHING is placed on that wall.
Min Fit Scale 0.5 = rows that would shrink below this fraction of the
              nominal opening are still dropped (a half-size door is not a
              sensible opening).
CONTRACT CHANGE (v2.6, documented): faces SHORTER than 'Opening Height' used
to get no opening at all; they now get a scaled-down one. This is the fix for
the "Fit is DEAD on my custom shape" report (UserShape2 in VM_Starter.blend):
his massing's tallest wall is 2.0 m and the default/demo Opening Height is
2.1-2.2 m, so the v2.5 row-fit gate rejected every wall and every layer went
empty (windows too: 0.25-0.9 m sill on top of that). Measured: 0 doors /
0 windows before, 8 doors / 4 windows after with the SAME sockets.

EXACT COUNTS (v2.6, HouseCraft 'choose exactly the number' parity)
-----------------------------------------------------------------
Count Mode 'Exact N' + Exact Count N + Exact Pick {'Spread', 'First'}:
the LAYER places EXACTLY N openings in total (all qualifying faces combined),
unless fewer candidates qualify (then all of them are placed). 'Spread'
(default) spaces the N picks evenly through the deterministic candidate list
(face order, then column/row); 'First' takes the first N in mesh order.
HONEST LIMIT: strict LARGEST-FACE-FIRST ordering is not expressible in
geometry nodes (Blender 5.2 has no domain sort) - 'Spread' is the documented
even-coverage variant. Gaps/sill/face filters still hold with precedence:
Exact N can only choose among the candidates the slot math produced.

MANUAL PLACEMENT (v2.6, HouseCraft ID-paint parity via VERTEX GROUPS)
--------------------------------------------------------------------
Manual Mask       ON = only slots whose position falls in the painted area
                  of the named vertex group are kept.
Manual Mask Group e.g. 'VM_Slots_Doors' / 'VM_Slots_Windows' (one group per
                  layer so you can paint each layer independently).
Manual Threshold  0.5 (painted-area interior).
HOW TO PAINT (GUI): select the host mesh -> Object Data Properties (green
triangle icon) -> Vertex Groups -> click '+', rename it to the exact group
name you put in 'Manual Mask Group' -> switch to Weight Paint mode (Ctrl+Tab
or the mode dropdown) -> paint the wall areas where the openings should go
(red = weight 1.0) -> switch back to Object Mode. The layer places openings
ONLY where the weight is >= 'Manual Threshold'. Painting is per VERTEX GROUP,
exactly Blender-native workflow - no custom tools.
PRECEDENCE: the painted area can only REMOVE candidates - it never adds one;
gap/sill/face-filter/fit rules hold first (documented precedence). The weight
is sampled 3 times per slot (at the slot position and +/- a quarter opening
along the wall) so vertex-group interpolation bleed across shared corner
vertices cannot leak openings onto unpainted walls.
HONEST LIMIT: the mask resolution is vertex-group INTERPOLATION (weights flow
across faces that share painted vertices). For sub-wall paint areas, subdivide
the wall first so the painted boundary lands on real vertices.

PACK SWAP (design packs by slots): the variant collections are plain sockets
('Primary Props'). Point one layer's socket at another <Pack>_WALLFLAT
collection and the SAME base model re-dresses in the new pack with identical
slot layout (see preview_packswap_a / _b / _pair in VM_Starter.blend).

BLACK-TRIANGLE FIX (v2.5): cladding tiles now STRADDLE the wall-contact plane
instead of growing inward from it. A wall fragment wound INWARD (extrusion /
fill leftovers) used to swallow its tiles inside the wall and z-fought their
coplanar backs, leaving a bare triangle that renders BLACK in the viewport.
Straddling covers every wall face whatever its winding (see
preview_bug_doors_before_crop / _after_crop). Architectural slabs (doors,
windows) still use the strict back-center wall-contact origin and DO orient to
the face normal - if your base mesh has inward-wound faces, run
Mesh > Normals > Recalculate Outside in edit mode before dressing (Blender
cannot infer inside/outside from a broken winding).

VM_RoofCap
----------
Pitch      roof slope angle (35 deg default)
Overhang   eave overhang in meters (0.25)
Style      Gable = ridge runs the full length of the region's LONG axis;
           Hip = ridge shortened by half the short side (on a square footprint
           this becomes a pyramid);
           Flat (v2.6) = NEAR-FLAT CAP over every flat top - subtle incline,
           thin edge fascia, NEVER any invented gable triangles (this is the
           right style for flat-topped/stepped designs like UserShape2)
Incline    (v2.6, Flat style) subtle cap incline along the region's long
           axis - a world ANGLE, default 2.5 deg (the roof reads flat but
           drains). Measured on UserShape2: exactly 2.5 deg per cap.
Fascia     (v2.6, Flat style) thin edge fascia skirt height at the cap's low
           edge (0.12 m; automatically raised so the low edge keeps >= 3 cm)
Roof Material  applied to the generated roof faces (empty = untouched)
Min Roof Face Size  (v2.4) up-facing quad tops whose short side is smaller
           than this do not get a GABLE - since v2.6 they get a FLAT CAP
           instead of being left open (see the coverage contract below)
Largest Face Only   (v2.4) only the largest qualifying top face gets a GABLE
           (single-roof mode for split tops) - since v2.6 every other top is
           FLAT-CAPPED, so single-roof mode no longer leaves holes

v2.6 COMPLETE-COVERAGE CONTRACT CHANGE (the gaping-hole fix):
every up-facing top face gets generated roof geometry - quads that qualify
take a gable/hip (or the Flat cap in Flat style) and EVERYTHING else (non-quad
tops from boolean/extrusion leftovers, undersized fragments, Largest-Face-Only
losers) gets a FLAT CAP. v2.5 skipped those regions cleanly and left the top
OPEN - the user's screenshot showed exactly that: gaping holes at the
tower/wing junctions exposing the interior. 'skipped' in verification_v2.json
now means 'no gable', never 'no roof'; the report's 'uncovered' list must stay
empty (verified on UserShape2 and the whole shape matrix).
Generated faces carry the 'vm_roofgen' face attribute: 1 = gable/hip faces,
2 = flat-cap faces - Fit never anchors doors/windows on either.

v2.4 PER-REGION BEHAVIOR: every qualifying up-facing QUAD top face (>= Min
Roof Face Size) is treated as its own roof region and gets its own gable/hip
along its LOCAL long axis - L-shaped and stepped compounds get one roof per
flat top instead of one rectangle over the whole bounding box. Unresolvable
regions (non-quad tops, undersized fragments) are skipped cleanly and
reported in verification_v2.json.

HONEST LIMITS (v2.4):
* VALLEYS ARE OUT OF SCOPE. Where two regions' roofs meet (a step wall
  between two tops), the gables/hips simply INTERSECT each other and the
  taller wall. The geometry stays clean (no stray wedges), but there is no
  valley flashing between intersecting roofs - add it by hand if needed.
* Tops are assumed LEVEL (within the up-facing test). A tilted top gets a
  level roof sitting on its center height.
* Split coplanar tops (one flat area modeled as several adjacent quads) get
  one roof PER QUAD with a seam; weld them or use Largest Face Only.
* Generated gable end triangles are vertical faces = Wall zone, and Fit never
  anchors doors/windows on them (the generated faces carry a 'vm_roofgen'
  marker that Fit always excludes).

Works on any host with flat top face(s): the 2m cube is the reference case,
CompoundTest (L-shaped stepped compound) is the reference case for compounds.

v2.4 SHAPE-ROBUSTNESS MATRIX (in VM_Starter.blend)
--------------------------------------------------
The engine is built for the real workflow: YOU model the building first
(edit-mode cube, extrusions, scaling - any structure), THEN the geometry
nodes dress it. The starter blend ships five dressed reference shapes:
  CompoundTest    L-shaped stepped compound (tall block + lower wing, concave
                  inner corner, two flat tops) - the reported user case
  CompoundScaled  the same compound non-uniformly scaled (x1.6 wider/taller),
                  object scale left UNAPPLIED like a user would
  TowerWing       tower + lower wing, multi-height, concave corners, plus two
                  roof regions the engine skips cleanly (a triangular top and
                  a 0.3 m top below Min Roof Face Size)
  Warehouse       wide low box (huge flat top -> one long gable)
  ReflowTest      the compound DRESSED FIRST, then edited (non-uniform mesh
                  scale + one more extrusion step) to prove live-edit reflow
Each shape runs the full stack (wall cladding + VM_RoofCap + roof cladding +
doors + windows) and is verified numerically per instance: door/window bases
equal THEIR OWN face base + sill, zero underground/detached parts, zero stray
roof faces, flat tops un-shingled, cladding counts match the independent
course formula. Acceptance renders: preview_compound.png /
preview_compound_closeup.png (the raised step-wall door) plus one shot per
shape (preview_compoundscaled / preview_towerwing / preview_warehouse /
preview_reflow_after.png).

LIVE-EDIT SEMANTICS (v2.4): editing the base mesh after the modifiers are on
re-flows the dressing automatically - parts re-anchor on the new faces,
cladding re-tiles to the new dimensions, roofs regenerate (see the 'reflow:*'
checks in verification_v2.json). One honest limit: Fit door/window POSITIONS
are random per face and face sizes feed that layout, so a big shape edit
reshuffles where the parts land (they stay correctly anchored to their faces,
just not in the same spots) - re-pick a Seed after major edits, exactly as you
would after changing Density. Cladding and roofs have no such limit.

KNOWN BEHAVIORS (surfaced on purpose, not bugs)
-----------------------------------------------
* Doors/Windows may re-shuffle positions after major base-mesh edits - re-pick
  the Seed to get a clean layout again (same as after changing Density).
* A door on a raised wall stands at THAT wall's own base edge (per-face
  anchoring) - it does not float down to the ground; YOU build the landing/
  stairs up to it.

ZONE CONTRACT CHANGE (v2.4, documented): 'Roof Slope' became the
'Roof Slope Min/Max' slope band and the Roof zone no longer includes flat
tops. Existing scenes keep working; re-check any hand-tuned Roof material
assignments on flat decks (they are Floor zone now).

EVALUATION NOTE (v2.4 engine internals): corner-sampled fields evaluate
differently in a Distribute Points selection context than in a store context
on Blender 5.2.2, so the node groups materialize all per-face frame data as
face attributes first and read it back as simple named attributes for every
selection/placement decision. If you extend the groups, follow the same
pattern (stores first, named-attribute reads in selections).

ASSET PREP RULES (variant collections)
--------------------------------------
* One object per variant, real-world scale, transforms applied.
* Convention: X = width (along the row), Y = depth (along the face normal),
  Z = height (along the row stack / world up).
* STRICT WALL-CONTACT ORIGIN (v2.1, enforced by build_engine.py/pack_ingest.py):
  the depth axis Y has its origin ON the wall-contact (back) face - local y = 0
  is the face that touches the wall, local +Y points outward along the face
  normal. Doors and handles additionally keep x centered and z at the base (so
  Drop To Ground works); cladding tiles keep x/z centered (so slot placement
  works). Because every variant's back face is at y = 0, a fitted part's
  wall-contact plane lands at the SAME distance for every variant depth - no
  more "some doors float off the wall, others sink behind the planks".
* Put variants in a dedicated collection and hide it from viewport/render
  (Geometry Nodes still reads it).
* v2.2: you no longer hand-prep packs - run pack_ingest.py (below) and it
  enforces all of the above automatically for ANY glTF/OBJ pack. The demo
  VM_Doors/VM_DoorHandles/VM_Windows collections are pure adapter output.
* Do NOT use the WoodShinglesMaterial demo spheres as tile variants - they are
  1m spheres with baked shingles. Use the generated Shingle_/Plank_ tile
  collections (built by build_engine.py with the library textures) instead.

PACK ADAPTER: pack_ingest.py (v2.2, zero configuration)
--------------------------------------------------------
One routine, NO pack-specific parameters: run the SAME command on any pack -
doors, windows, shingles, props - and get engine-ready normalized variant
collections plus an ingest report:

  cd <blender dir> && ./blender -b --python pack_ingest.py -- \
      [--out DIR] [--save-blend] <pack.gltf|pack.obj|pack-dir> [...]

It has been run unmodified on WornWoodenDoorsPack and all 4 window packs
(WeatheredWoodenWindow, BrokenWindow01, BrokenWindow07, MedievalWindows);
the <Pack>_ingest.json files in this folder are that run's output.

What it does per object (deterministic, thresholds are generic constants):
  1. imports the pack; non-mesh leftovers (empties/rig nodes) are dropped and
     counted in the report
  2. normalizes scale to real-world meters from the authored mesh geometry:
     max dimension > 40 units -> cm-scale pack, auto-scaled 0.01 (logged per
     object and per pack); > 4 m or < 0.05 m in every axis -> flagged
  3. auto-orients: thin axis -> Y (depth), largest -> Z (height), middle -> X
     (width); proper rotation only (never mirrored); origin at the engine's
     wall-contact contract (slabs: x centered, y=0 on the back face, z at the
     base; tiles: x/z centered; props: centered on the ground). The pack's
     SHOWROOM LAYOUT (object transforms, e.g. shutters posed swung-open) is
     discarded - a variant is its authored shape, re-derived from the mesh.
  4. classifies by bbox aspect (depth = thinnest extent after orienting):
       WALLFLAT  depth <= 25% of min(width, height) AND flat  -> wall slab
       TILE      flat AND small (max(w,h) <= 0.6 m)            -> cladding tile
       PROP      anything else (handles, boxes, chunky parts)
  5. auto-quarantines unfit meshes into <Pack>_Quarantine with per-object
     reasons - they NEVER mix into Fit collections:
       degenerate          some axis < 4 mm (zero-thickness sheets, glass)
       multi-part leftover >=2 connected shells that fall apart into loose
                           clusters (gap > max(2 mm, 0.4% of size))
       non-flat (ajar)     PCA thickness > 1.05 x bbox depth: the panel is
                           swung/splayed inside its own bbox, so a
                           bbox-normalized wall fit leaves it hanging in the
                           air off the wall plane (this is the "floating door"
                           failure mode - e.g. the WornWoodenDoorsPack's
                           splayed "Worn Doorframe_*" pieces are quarantined
                           here and never reach VM_Doors)
  6. writes <Pack>_ingest.json (counts per class, per-object decisions, scale
     factors, quarantine reasons) and prints the same table.

WINDOWS LAYER (v2.2)
--------------------
The starter's fifth modifier is another VM_SceneDetailer in Fit mode with the
VM_Windows collection - adapter output from WeatheredWoodenWindow (louvered
shutter slabs) plus a BrokenWindow01 window unit as a second style. SAME node
group as the doors, different collection: that is the "different pack, same
engine" proof. Windows use the identical wall-contact contract as doors
(Backing Offset 0.0435, Embed 0.02 -> back plane tangent to the plank outer
plane) and are placed with a deterministic RESEED (build_engine.py searches
seed space on a hidden rig whose host geometry is identical to the starter's,
because the engine samples only the host mesh): the chosen seed keeps windows
on the walls (never on roof gables, never hanging off a wall corner), at
window height (base 0.25-1.05 m, top below the wall top), and with ZERO
window/door, window/window and window/plank bbox intersections (the same
world-bbox measurement as the door/plank check). To place windows in your own
scene: add a Fit-mode VM_SceneDetailer, point Primary Props at a windows
collection from pack_ingest, and change Seed until placement suits your scene.

STRICT WALL-CONTACT / KEEP-CLEAR-OF-CLADDING CONTRACT (v2.1)
------------------------------------------------------------
Fit places the variant's back face at: base wall plane + (Backing Offset -
Embed) along the outward face normal. To mount a part ON TOP of a cladding
layer, set Backing Offset to the cladding buildup in front of the base wall
plus any clear gap you want, and keep Embed as the small sink.

Worked demo numbers (VM_Starter.blend "VM_SceneDetailer_Door" + "_Windows"):
  wall planks      : 0.02 m thick tiles sitting ON the wall (y=0 at the wall);
                     measured plank outer plane 0.02315-0.02317 m (bend+jitter)
  door modifier    : Backing Offset 0.0435, Embed 0.02
  -> door back plane lands 0.0235 m off the base wall = TANGENT to the plank
     outer plane (0.0003-0.0005 m contact-level gap to the frontmost planks -
     no hairline daylight at the junction), still inside the accept(a)
     tolerance band (planks_thickness + 0.005 +/- 0.005) and never behind the
     planks
  -> door front face is ~0.09-0.11 m proud of the plank outer plane (the door
     slabs are 0.086-0.108 m thick; v2.2 VM_Doors holds only the adapter's
     wall-flat slabs - the pack's deeper splayed "Worn Doorframe_*" pieces are
     quarantined as non-flat (ajar) and never fitted)
  -> zero world-bbox intersection with any plank (contact-level pairwise gap)
  (the wall plank cladding demo uses Jitter 0.002 m so this gap holds exactly;
   the demo door Seed 229 is the deterministic seed whose 3 fitted doors all
   clear the wall corners - no door bbox reaches a perpendicular wall's planks;
   windows use the same contract and a deterministic reseed - see WINDOWS LAYER)
Measured on the delivered blends by build_engine.py and logged in
verification_v2.json (checks accept(a), accept(b), accept(c) - v2.2: accept(c)
covers "all wall-flat door variants" instead of the old fixed "8 door variants",
since VM_Doors is now adapter-filtered; every other check is unchanged).
See preview_door_closeup.png / preview_window_closeup.png /
preview_starter_house.png for the visual proof.

TEXTURES ARE PACKED (v2.1)
--------------------------
Every image datablock is PACKED into each delivered .blend before saving
(bpy.ops.file.pack_all() + per-image pack fallback). The files open with zero
missing/magenta textures even if ViperMeshAssets is absent - no image filepath
outside the blend is load-bearing. verification_v2.json logs
"images_packed: N/N" per delivered blend (all image datablocks, all packed).

REBUILDING FROM SCRATCH
-----------------------
  cd <blender dir> && ./blender -b --python build_engine.py
Deterministic: fixed seeds, same output every run. The script also re-runs the
full numeric verification suite and re-renders the preview PNGs.
